# 작은 정원 이미지 제작 가이드

현재 새싹 캐릭터와 정원 A·B·C의 그림체를 유지하면서 배경, 꾸미기 소품, 캐릭터 동작을 계속 제작하기 위한 기준이다. **같은 원본 기준 이미지와 아래의 고정 규칙을 매번 함께 사용한다.** 생성 프롬프트만 복사하고 기준 이미지를 생략하지 않는다.

이 가이드의 수치 중 원본 해상도와 파일 정보는 실제 파일 값이다. 비율·여백·배치 수치는 앞으로 일관성을 맞추기 위한 제작 기준이며, 기존 이미지 모두를 측정한 값은 아니다. AI 생성에는 편차가 있으므로 원본 대조와 앱 크기 검수를 통과한 결과만 사용한다.

## 1 기준 이미지와 우선순위

판단 순서는 현재 사용자의 구체적인 수정 요청 → 원본 기준 이미지 → 테마별 규칙 → 공통 규칙 → 이번에 추가할 내용이다. 사용자가 그림체 변경을 요청하면 변경 범위만 적용하고, 요청하지 않은 특징은 보존한다.

| 역할 | 기준 파일 | 적용 범위 |
|---|---|---|
| 캐릭터 정체성 | `references/character_master.png` | 잎 수, 얼굴, 몸통, 짧은 팔다리, 색 |
| 기존 동작 예시 | `references/character_poses.png` | 손의 단순화, 표정, 소품을 드는 방식 |
| A 공간 기준 | `references/theme_a_decorated.png` | 둥근 집과 나무 그늘 마당 |
| A 빈 배경 | `references/theme_a_empty.png` | 아이템 없이 보존할 공간 구조 |
| A 소품 기준 | `references/theme_a_props.png` | 재질, 윤곽, 시점, 그림자 |
| B 공간과 소품 | `references/theme_b_decorated.png`, `theme_b_empty.png`, `theme_b_props.png` | 연못과 툇마루 |
| C 공간과 소품 | `references/theme_c_decorated.png`, `theme_c_empty.png`, `theme_c_props.png` | 온실과 퍼골라 |

이전의 꽃이 빽빽하고 폭포·다리가 있는 정원은 이 제작 프로필의 기준에서 제외한다. 이전 3D 토이 캐릭터도 이번 2D 이미지의 재질 기준으로 섞지 않는다.

원본 11개는 읽기 전용 기준으로 취급한다. `reference_manifest.json`에 원본 위치, 크기, SHA256을 기록했다. 새 결과물로 같은 이름의 원본 파일을 덮어쓰지 않는다. 새로 생성한 결과만을 다음 생성의 유일한 기준으로 삼지 않는다.

## 2 제작 프로필 선택

**A안을 기본 제작 프로필로 둔다.** 앞서 제안한 방향을 작업용 기본값으로 정한 것이며, 사용자가 A안을 최종 선택했다는 뜻은 아니다. 사용자가 B·C를 지정하거나 해당 원본을 수정 대상으로 첨부하면 그 프로필이 우선한다. 한 번의 제작 묶음에는 하나의 프로필만 적용한다.

| 프로필 | 고정 공간 | 어울리는 추가 요소 | 섞지 않는 요소 |
|---|---|---|---|
| A 나무 그늘 마당 | 오른쪽 위 녹색 둥근 지붕 집, 왼쪽 큰 나무, 중앙 잔디, 아래에서 집으로 이어지는 곡선 길 | 곡선 벤치, 해먹, 작은 찻상, 화분 선반, 새 물그릇 | 강·폭포·다리, 온실, 긴 툇마루 |
| B 연못과 툇마루 | 위쪽 낮은 집과 툇마루, 왼쪽 연못, 중앙 잔디와 오른쪽 곡선 길 | 낮은 찻상, 방석, 라운지 의자, 돌 조명, 책 수레 | 흐르는 강·폭포, 큰 교량, 온실 |
| C 숲속 온실 | 오른쪽 위 온실, 왼쪽 위 퍼골라, 넓은 자갈 마당, 아래쪽 진입 징검돌 | 분갈이 작업대, 허브 상자, 씨앗 수납장, 피크닉 소품 | 주거용 오두막, 연못·강·폭포 |

새 아이템을 추가한다는 요청은 집·나무·길·카메라를 새로 배치하라는 뜻으로 확대하지 않는다. 기존 공간의 확장과 완전히 새로운 맵 제작은 별도 작업이다.

## 3 공통 그림체

따뜻하고 차분한 2D 픽셀 페인팅이다. 큰 색면과 읽기 쉬운 픽셀 덩어리로 형태를 만들고, 나무·돌·천의 재질을 간단한 명암으로 구별한다. 현재 그림은 모든 요소가 하나의 픽셀 격자에 엄밀히 맞는 전통적 도트 스프라이트와는 차이가 있다. 가는 무작위 노이즈를 늘리거나 저해상도 필터로만 픽셀 느낌을 내지 않는다.

| 요소 | 유지할 특징 |
|---|---|
| 시점 | 기준 이미지와 같은 위에서 내려다보는 3/4 게임 시점. 지평선이 보이지 않는 정원 화면 |
| 원근 | 바닥 접지와 가구 윗면이 함께 보임. 카메라 각도를 임의의 도수로 다시 정의하지 않고 원본과 비교 |
| 빛 | 부드러운 낮빛. 소품은 기준처럼 위·왼쪽이 밝고 아래·오른쪽에 짧은 접촉 그림자 |
| 윤곽 | 짙은 녹갈색·갈색 계열. 캐릭터는 더 또렷하고 배경 잔디는 약하게 |
| 목재 | 꿀빛 갈색, 단순한 판재와 둥근 모서리. 과한 나뭇결·상처·광택 없음 |
| 돌 | 따뜻한 회베이지, 둥근 큰 면과 소량의 이끼 |
| 천 | 크림·세이지 색, 소박한 접힘. 반짝이는 실크·플라스틱 질감 없음 |
| 식물 | 둥근 잎 덩어리, 식별되는 큰 윤곽. 화면 전체에 꽃과 밝은 점을 흩뿌리지 않음 |

색상은 `palette.svg`와 `production_rules.json`의 목표색을 참고한다. 캐릭터 크림·잎·볼의 색은 원본에서 근사 샘플링했고, 환경색은 앞으로 사용할 제작 목표값이다. HEX가 같다는 이유만으로 스타일 검수를 통과시키지 않는다.

## 4 새싹 캐릭터 고정 규칙

**아이보리색 둥근 머리와 작은 몸통이 자연스럽게 이어지고, 머리 위에는 정확히 두 장의 초록 잎이 있다.** 정면 캐릭터는 검은 세로형 작은 눈, 작은 주황색 U자 웃음, 복숭아색 볼, 짧은 크림색 팔과 두 개의 초록 발을 갖는다.

- 머리가 몸보다 훨씬 크고, 몸은 짧고 도톰하다. 목을 길게 빼거나 허리를 잘록하게 만들지 않는다.
- 손은 작은 둥근 장갑형이다. 사람의 긴 팔, 팔꿈치, 다섯 손가락을 넣지 않는다.
- 팔의 노출 길이는 얼굴 폭의 약 1/4 안쪽을 작업 목표로 삼는다. 소품을 들 때에도 팔을 늘려 해결하지 않는다.
- 정면 눈 간격과 높이, 잎의 크기와 기울기는 `character_master.png`를 따라간다. 숫자로 임의 재설계하지 않는다.
- 의상·모자·코·귀·속눈썹·추가 잎은 이번 요청에 있을 때만 추가한다. 잎이 소품에 가려져 사라지지 않게 한다.
- 움직임이나 표정을 바꿀 때에는 얼굴·머리·잎의 크기를 고정한다. 한 시트 안에서 캐릭터 크기가 달라지면 다시 맞춘다.

새 동작은 **한 장의 캐릭터 → 기준과 비교 → 동작 시트** 순으로 확장한다. 애니메이션은 그림 개수만 맞춰 끝내지 않고 반복 연결, 접지점, 실루엣 흔들림을 실제 재생으로 확인한다.

## 5 배경과 꾸미기 밀도

배경은 캐릭터가 살아가는 공간이고, 소품은 놓았을 때 변화가 보이는 요소다. 중앙을 모두 채우지 않는다.

- 앞으로 제작할 완성 정원의 목표는 중앙에서 연결되는 걷기 영역 약 35~45%다. 이 수치는 제작용 가이드이며 현재 기준 그림을 측정한 점유율은 아니다.
- 기본 배치 예시는 테마당 소품 그룹 6개를 기준으로 한다. 사용자가 더 많은 아이템을 요청하더라도 한 화면의 배치 수를 동시에 늘리지는 않는다.
- 큰 소품은 가장자리에 두고, 중앙에는 캐릭터와 작은 상호작용 소품을 남긴다. 출입문과 길을 막지 않는다.
- 꽃은 2~3곳의 작은 군집을 출발점으로 삼는다. 색을 추가해야 한다면 흰색·크림·연한 노랑을 먼저 쓴다.
- 나무의 밝은 잎 점, 잔디의 점무늬, 돌의 균열, 물의 흰 반짝임이 한꺼번에 강해지지 않게 한다.
- 실제 캐릭터를 기존 앱 표시 크기로 올렸을 때 첫눈에 찾을 수 있어야 한다. 화면을 작게 줄여 봐도 캐릭터와 주요 버튼의 위치가 읽혀야 한다.

완성 예시 그림과 편집용 에셋은 구분한다. 완성 예시의 소품은 배경에 그려져 있어 움직이지 않는다. 앱에서 옮기려면 빈 배경과 개별 투명 소품을 사용한다. 생성으로 만든 완성 그림과 재생성한 소품이 픽셀 단위로 완전히 일치한다고 표현하지 않는다.

## 6 파일과 시트 규격

| 종류 | 생성·내보내기 기준 |
|---|---|
| 정원 배경과 완성 예시 | 가로 16:9에 가까운 구도. 현재 기준 파일은 1672×941. 실제 출력 크기를 확인해 기록 |
| 원본 배경을 수정할 때 | 원본 프레임과 공간을 최대한 유지. 결과 크기·문·길·벽 위치를 대조. 크기가 같아도 지형이 완전히 같다고 가정하지 않음 |
| 캐릭터와 소품 | 진짜 알파 채널이 있는 투명 PNG. 흰색·검정·체커보드를 배경으로 그리지 않음 |
| 소품 시트 | 같은 테마의 6개를 3열×2행으로 구성. 셀별 중앙 정렬, 넉넉한 간격, 요소 간 비접촉 |
| 캐릭터 시트 | 통일한 크기와 같은 바닥 기준. 동작 이름·순서·프레임 수를 요청 전에 명시 |
| 개별 스프라이트 | 분리 후 같은 묶음 안에서 캔버스 크기를 통일. 보이는 콘텐츠와 기준점은 별도 기록 |
| 접지 기준 | 아래쪽 중앙을 기본값으로 사용. 그림자 포함 바운딩 박스와 실제 발 접지점은 시각 검수로 구별 |
| UI 글자 | 그림에 고정하지 않고 앱의 텍스트로 표시. 생성 이미지에는 한글·영문 문구를 넣지 않음 |
| 변형 파일 | 배경은 PNG 원본과 WebP 사본. 앱 아이콘은 요구되는 정확한 크기일 때만 별도 변환 |

현재 A 소품은 608×432, B는 512×480, C는 544×400으로 정리돼 있다. **파일 크기 차이를 물건의 실제 크기 차이로 해석하지 않는다.** 같은 캐릭터를 놓은 화면에서 테이블·벤치·화분 크기를 따로 맞춘다. 도트 느낌이 필요하면 앱의 축소 표시를 확인하고, 원본 전체에 임의 선명도·블러·디더링 필터를 걸지 않는다.

출력 크기 2048을 프롬프트에 적었다는 이유만으로 2048 원본이라고 표기하지 않는다. 실제 파일의 폭과 높이를 manifest에 쓴다.

## 7 매번 반복하는 제작 순서

1. **작업 명세 작성** — 테마, 에셋 종류, 수량, 추가 내용, 바꿔도 되는 것과 유지할 것을 `templates/job_brief.json`에 기록한다.
2. **기준 이미지 선택** — 배경은 같은 테마의 빈 배경을 수정 대상으로, 새 소품은 같은 테마의 소품 시트와 완성 정원을 스타일 기준으로 첨부한다. 캐릭터가 있으면 캐릭터 원본도 첨부한다.
3. **프롬프트 구성** — `templates/prompt_templates.txt`의 공통 고정 문장과 해당 템플릿을 결합한다. 각 첨부 파일이 수정 대상인지 스타일 기준인지 분명히 적는다.
4. **소량 제작** — 새 디자인은 먼저 소품 1종 또는 작은 시안으로 기준과 맞는지 확인한다. 확인된 디자인만 시트나 묶음으로 늘린다.
5. **원본과 대조** — 캐릭터 정체성, 테마 구조, 시점, 색·명암, 밀도를 차례로 확인한다. 새로운 결과끼리만 비교하지 않는다.
6. **단일 원인 수정** — 팔이 길면 팔만, 배경이 복잡하면 배경의 잔무늬만 수정한다. 맞는 부분을 다시 디자인하지 않는다.
7. **기술 검사와 정리** — 알파, 잘림, 파일 크기, 이름, 시트 순서, 기준점, 앱 표시 크기를 확인한다. 원본·개별 파일·시트·메타데이터·프롬프트·검수 결과를 저장한다.

기준 이미지는 결과마다 계속 누적 첨부하지 않는다. 보통 한 작업에 필요한 2~3장의 원본을 선택한다. 캐릭터가 없는 소품 작업에는 캐릭터 시트를 불필요하게 넣지 않는다.

## 8 검수 기준

아래의 필수 조건은 점수와 무관하게 확인한다. 어긋나면 그대로 배포용 묶음에 넣지 않고 요청된 범위 안에서 수정한다.

| 필수 조건 | 실패 예 |
|---|---|
| 캐릭터 정체성 | 세 번째 잎, 긴 팔, 추가 팔다리, 달라진 얼굴 |
| 테마와 공간 | A에 강이 생김, B의 연못이 오른쪽으로 이동, 소품 추가 중 집 모양이 바뀜 |
| 금지 요소 | 의도하지 않은 글자·UI·프레임·로고·다른 캐릭터 |
| 파일 사용성 | 잘린 잎·가구 다리, 가짜 투명 배경, 셀 간 붙음, 읽을 수 없는 파일 |

스타일은 원본을 보면서 각 항목을 0·1·2점으로 검토한다. 0은 원본과 뚜렷하게 다름, 1은 작은 수정 필요, 2는 같은 세트에 자연스럽게 들어감을 뜻한다.

| 항목 | 확인할 내용 |
|---|---|
| 형태 | 캐릭터 비율 또는 소품의 둥글고 단순한 형태 |
| 색과 명암 | 크림·세이지·목재색의 균형, 배경보다 또렷한 주인공 |
| 시점과 빛 | 같은 윗면 노출과 접지, 짧은 접촉 그림자 |
| 픽셀 표현 | 큰 픽셀 덩어리, 과한 노이즈·매끈한 3D 광택 없음 |
| 구성과 축소 가독성 | 여백, 소품 분리, 작은 화면에서의 식별 |

필수 조건을 모두 충족하고 10점 만점 중 9점 이상이며 0점 항목이 없는 결과를 패키징 기준으로 삼는다. 이는 제작 중 사람이거나 작업 에이전트가 기록하는 시각 평가이며, 자동으로 스타일 일치를 보증하는 수치는 아니다.

## 9 이름과 변경 기록

새 결과는 `a_decor_birdhouse_v001.png`처럼 테마·종류·대상·버전을 이름에 넣는다. 빈 배경은 `a_background_empty_v001.png`, 완성 예시는 `a_scene_decorated_v001.png`, 캐릭터는 `a_character_waving_v001.png` 형식을 쓴다. 기존 원본에 덮어쓰지 않는다.

작업마다 요청 내용, 사용한 기준 파일과 해시, 최종 프롬프트, 실제 해상도, 시트 셀 순서, 개별 파일과 기준점, 검수 결과를 보존한다. 템플릿은 `templates/delivery_manifest.json`과 `templates/review_record.json`에 있다. 단순 도구 출력이나 프롬프트만 보고 검수 완료라고 기록하지 않는다.
