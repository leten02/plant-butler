# 식물집사 — 스펙과 서비스 맥락

발표용 데모의 원 요청(스펙), 팀 회의 결과, 구현하면서 정한 결정을 한곳에 모은 문서.
화면 참고 이미지는 `docs/reference/`에 있다.

## 1. 서비스 맥락 (팀 회의 결과)

**한 줄 요약.** 우울증 관련 정기 상담·집중 치료 과정을 마친 뒤 일상 복귀가 어려운 사람이, 작은 현실 활동부터
시작해 스스로 하루를 계획하도록 돕는 정원 게임형 앱. 서비스명 "식물집사", 부제 "멈춘 일상에, 작은 시작을".

**누구의 어떤 문제인가**
- 초기 검증 대상: 해당 과정을 계획적으로 마친 후 6개월 이내의 성인 중 일상 활동에 어려움을 느끼는 사람.
- 6개월은 **초기 모집 범위**일 뿐, 의학적으로 정해진 회복 기간도 앱 이용 기한도 아니다.
- 증상은 나아졌지만 외출·자기돌봄·관계 활동을 시작하고 지속하거나, 중단 후 다시 시작하기 어렵다.
  작은 시도가 변화로 잘 느껴지지 않는다.
- 정기적인 지원을 마친 뒤 스스로 일상을 계획하는 과정에서 어떤 도움이 부족한지 확인하려 한다.

**왜 이 문제를 해결하려는가.** 2024년 메타분석에서 우울증 관해 이후에도 기능상의 어려움이 남을 수 있음이 보고되었다.
따라서 증상 호전과 별개로, 원하는 일상을 실행하도록 돕는 지원의 필요성을 살펴보려 한다.

**무엇을 구현하는가(회의 정리).** 자유롭게 이동하고 꾸미는 작은 가로형 픽셀 정원과 새싹 캐릭터 / 오늘의 여력에 따른 활동 선택·축소·교체와 직접 계획 /
실행 후 짧은 회고와 정원에 쌓이는 시각적 기록 / 쉬어도 기록을 보존하고 밀린 과제 없이 돌아오는 복귀 흐름.
실제 식물 관찰은 선택형으로 검토하고, **이웃 방문·식물 나눔·하드웨어는 후속 기능**으로 분리한다.

**왜 가능성을 기대하는가.** 디지털 행동활성화 메타분석(12개 RCT, 3,274명)과 Moodivate RCT(649명)에서 활동 계획·실행 지원의 가능성을 확인했다.
자율성 지원 연구를 참고해 사용자가 선택과 계획의 주도권을 갖게 설계했다.
다만 정원·캐릭터·3단계 구조가 회복기 사용자에게 주는 **추가 효과는 직접 검증**해야 한다.

**무엇을 다르게 풀고 어떻게 검증하는가.** Quabble·Finch에도 자기돌봄과 게임 요소가 있으므로 캐릭터나 미션 자체를 차별점으로 내세우지 않는다.
차별점은 종결 이후의 일상 재시작과 자율적 계획 지원이다. 평가 우선순위: 실제 활동의 실행·반복·재시작, 직접 계획 경험, 사용자 부담.

**하지 않는 것.** 상담·진단·치료를 제공하지 않는다. AI로 마음 상태를 판정하지 않는다. 재발 예방 효과는 현재 주장하지 않는다.

**핵심 흐름.** 활동 선택 → 현실 실행 → 짧은 회고 → 정원의 변화. 게임 속 산책이 아니라 실제 생활에서 해보는 활동이다.

**핵심 기능(5)**: 여력에 맞게 고르기 / 부담되면 줄이기 / 기록을 공간에 남기기 / 쉬었다 다시 시작하기 /
실제 식물 관찰(원할 때만 선택 — **이번 데모에는 구현하지 않음**; 이웃 방문·식물 나눔·하드웨어는 후속 기능).

**3단계.** 날짜로 정하지 않는다. 필요하면 이전 도움을 다시 선택한다(그래서 탭을 잠그지 않는다).
1. 미션: 앱이 제안하고 내가 고른다. 시작하기 어려우면 가능한 크기로 줄인다.
2. 일상 연결: 내가 시간과 장소를 정한다(예: 점심 식사 후 · 집 근처 · 가능한 만큼). 다시 하고 싶은 활동을 생활 속에서 반복한다.
3. 하루 설계: 오늘 할 일과 성공 기준을 정한다. 해본 뒤 돌아보고 다음 계획을 바꾼다.

**날의 상태**: 부담스러운 날 → 더 작게 · 다른 활동 · 쉬기. 쉬었다 돌아온 날 → 정원과 기록은 그대로, 밀린 과제 없음.

**성공 기준은 접속 시간이 아니라 원하는 현실 활동.** 최종 목표는 "앱 없이도 원하는 일상을 스스로 이어가기".

**검증 상태(UI·발표에서 효과를 단정하지 말 것)**: 회복기 적용 효과와 재발 예방은 검증 전(재발 예방은 주장하지 않음). 정원·캐릭터·3단계의 추가 효과는 파일럿에서 검증할 예정.
앱 UI에는 "우울·증상·치료·상담" 단어를 쓰지 않는다(서비스 소개 자료에는 쓰이지만 앱 안에서는 아니다).

## 2. 설계 원칙 (어기지 말 것)
- 연속 기록(스트릭), 벌점, 미완료 표시, 정원 시들기·초기화 없음.
- 안 한 일은 기록하지 않음. 해낸 것만 쌓임.
- 칭찬 대신 사실 피드백: "대단해요!" 금지 → "이번 주 집 앞 걷기 3번째예요."
- 하루 활동은 최대 3개. 상한에 닿으면 "오늘은 여기까지 해도 충분해요".
- "오늘은 쉬기"도 정상적인 선택지. 고르면 캐릭터가 같이 쉬는 모습으로 바뀜.
- 재촉하는 알림, 랜덤 보상, 유료 요소 없음. 씨앗 봉투는 꽝·등급·중복 없음.
- 캐릭터 말투: 존댓말, 부드럽고 짧게. 금지 표현: "오늘 안 했네요", "기록이 끊겼어요", "더 노력해요".
- 게임은 효과를 내는 장치가 아니라 형식. 앱에 오래 붙잡아 두는 게 목표가 아니고 행동은 화면 밖에서 일어남.

## 3. 원 요청 스펙 요약
- 스택: Vite + TypeScript + Phaser 3(정원 씬) + HTML/CSS 오버레이. 가로 844×390, 세로면 "화면을 가로로 돌려주세요".
  저장은 localStorage(try/catch, 실패해도 동작). PWA 매니페스트만(오프라인 캐시 선택). 서버·로그인·결제 없음.
- 그래픽: 픽셀 아트, Kenney CC0 에셋 권장(출처를 README에), 없으면 도형 플레이스홀더. 기존 게임 캐릭터를 닮지 않게.
- 마스코트 "새싹이": 하얀 찹쌀떡 몸, 두 잎 새싹, 분홍 볼, 32×32 스프라이트(기본·걷기 2프레임·기쁨·쉬는 중).
- 화면: 01 정원 홈 / 02 여력 체크(하루 첫 진입) / 03 활동 패널(미션·일상 연결·하루 설계) / 04 완료와 회고 /
  05 기록(+도감) / 06 꾸미기 / 07 설정.
- 데이터: activities 15개 내외, logs, garden. 직접 계획 비율(하루설계 출처/전체)은 계산하되 **디버그 패널에서만** 노출.
- 데모 모드: [다음 날로], [샘플 데이터 채우기](2주치).
- 완료 기준: 844×390과 데스크톱에서 스크롤 없이 한 화면 / 아무것도 안 해도 경고·불이익 문구 없음 /
  하루 3개 상한·쉬기·더 작게 동작 / 새로고침해도 정원과 기록 유지.

## 4. 구현하면서 정한 것 (해석)
- 스펙 02의 "여력 체크"는 하루 첫 진입 모달. 첨부 목업 02의 "현실 활동 계획"은 활동 패널의 미션 탭 상세 화면.
- 여력이 "조금 무거워요"면 1~2분짜리 활동만 제안. 지나가기를 누르면 보통으로 처리.
- 완료할 때마다 소품이 하나 생김(꽃·꽃·화분·꽃·등불·꽃·벤치 순환). 씨앗 봉투는 **하루 1개**, 완료한 날과 쉬기를 고른 날 모두 지급.
  봉투를 열면 아직 못 만난 식물이 화단에 심김(12종, 다 만나면 더 안 나옴). 안 연 봉투는 쌓이되 독촉 문구 없음.
- 도감에는 심어진 식물만 보이고 빈칸·"n/12" 같은 수집 압박 표시는 없다.
- 일상 연결 탭은 3번째 기록부터, 하루 설계 탭은 7번째 기록부터 "해볼까요?" 표시만 붙는다(잠그지 않음).
- 하루 설계 탭은 패널 높이 때문에 [오늘은 쉬기]·하단 안내를 뺐다(미션·일상 연결 탭에는 있음).
- 직접 쓴 계획은 소요 시간을 정하지 않아 "얼마나"에 "내 속도로"로 표시.
- 소리 파일은 없고 "소리 끄기"는 설정 값만 저장한다.
- 샘플 데이터는 오늘을 비우고 최근 이틀의 봉투를 열지 않은 채 둔다(시연 때 직접 해볼 수 있게).
- 그래픽: 팀 가이드(`art/guide`, A 테마 나무 그늘 마당)로 교체. 배경 한 장 + 걸을 수 있는 다각형, 소품 6종(벤치·찻상·새 물그릇·화분 선반·해먹·꽃 화분)은 완료할 때마다 이 순서로 생긴다. 새싹이는 가이드의 캐릭터 포즈(기본·손 흔들기·기쁨·쉬는 중)를 쓰고 걷기는 모션으로 표현한다. 가이드에 없는 도감 식물 12종과 UI 아이콘·프레임은 ChatGPT로 만든 그림을 쓴다.

## 5. 상태 (2026-10-27)
M1~M5 구현 완료, 사용자가 화면 확인 완료. 아직 하지 않은 것: 실제 식물 관찰 기능, 소리, Kenney 에셋 교체, 오프라인 캐시, 프로젝트 전용 git 저장소.

### 2026-10-27 UX 보완 (팀 공유 전 혼자 다듬는 중)
사용자가 꽃밭 구분이 잘 안 가고, 활동 패널의 "바꾸기"/"더 작게"가 별로고, 소품을 치울 방법이 없다고 지적 → 세 가지 보완:
1. **꽃 시각 구분** — `plants.json`에 12종마다 다른 `pattern`을 줘서(민들레=촘촘한 가느다란 꽃잎, 클로버=3엽, 수국=작은 꽃송이 뭉치 등) `assets.ts`가 종마다 다른 실루엣을 그리게 함. 화단 배경의 랜덤 장식 꽃 90개와 풀밭의 12% 랜덤 꽃 점은 제거(흙 질감으로 대체) — "장식"과 "내가 모은 식물"이 안 섞이게.
2. **바꾸기/더 작게** — `swapCandidate()`가 고정 순서 대신 무작위로 하나를 고름. "더 작게" 버튼에 목표 분(`더 작게 (n분)`) 표시 추가. (활동 체인 자체는 안 건드림 — 가벼운 범위로 합의.)
3. **창고(신규)** — 꾸미기 모드에서 소품을 끌지 않고 짚기만 하면 창고로 이동(`storeDecor`), 꾸미기 바의 "창고 N" 버튼 → 목록에서 꺼내기 → 칸을 짚어 다시 심기(`takeFromStorage`). 식물(도감)은 대상 아니고 소품(꽃·화분·가로등·벤치)만. `AppState.garden.storage` 필드 추가(기존 저장본은 `createState()` 기본값으로 자동 채워짐).

**사람 확인 필요** — 레이아웃·드래그·그래픽을 직접 건드렸으므로 아직 브라우저로 직접 확인 전: (a) 12종 꽃이 실제로 구별되어 보이는지, (b) 꾸미기 모드에서 "짚기(창고로)"와 "드래그(위치 이동)" 구분 임계값(타일의 30%)이 적당한지, (c) 창고 모달(420px) 레이아웃.

변경 파일: `core/types.ts`, `core/store.ts`, `core/rules.ts`, `core/plants.ts`, `core/data/plants.json`, `core/copy.ts`, `core/events.ts`, `scene/assets.ts`, `scene/GardenScene.ts`, `ui/activityPanel.ts`, `ui/decorate.ts`, `styles/overlay.css`. 테스트(`rules.test.ts`/`copy.test.ts`) 추가, `npm test`·`npm run build` 통과 확인.

### 2026-10-27 "대화" 목업 (챗봇 방향성 미리보기)
기존에는 HUD의 💬 "대화" 버튼이 활동 패널을 그대로 열었음(스펙 화면 목록에 "대화"는 원래 없던 화면). 발표에서 "나중엔 챗봇형으로 간다"는 방향을 보여주려고 실제 대화 로직 없이 정해진 대사 3줄을 순서대로 보여주는 목업(`ui/talk.ts`, `copy.talk`)으로 교체. `flow.ts`의 `talk` 액션이 `openTalk()`을 연다. 실제 대화 엔진은 아직 없음 — 다음에 이 자리를 채우려면 새 작업으로 다시 브레인스토밍해야 함.

### 2026-10-27 심은 식물도 창고로 — 창고 모델 통합, 화단 위치 이동은 보류
사용자가 브라우저에서 대화·창고 테스트 후, 심은 꽃(도감)도 소품처럼 옮기고 창고에 넣을 수 있게 해달라고 요청. 결정한 것:
- 식물은 여전히 화단 칸(`isPlantTile`)에만 심을 수 있음 — 원래부터 그랬고 바뀐 건 없음.
- **식물도 소품과 동일한 조작**(꾸미기 모드에서 짚기=창고, 끌기=재배치)을 쓰게 통합. `AppState.garden.storage`를 `StoredDecor[]`에서 식물까지 포함하는 판별 유니언 `StoredThing`(`type: 'decor' | 'plant'`)으로 교체. 식물을 창고에 넣어도 처음 만난 날짜(`date`)는 그대로 유지(도감 표시용). 꺼낼 때 소품은 아무 풀밭 칸, 식물은 화단 칸만 가능(`canPlace` vs `canPlacePlant`).
- 창고 목록은 종류별로 정렬(소품: 꽃→화분→가로등→벤치, 그다음 식물: 이름순) — `ui/decorate.ts`의 `sortedStorage()`.
- **화단(텃밭) 자체의 위치를 나중에 바꾸는 기능은 일단 보류**(사용자가 명시적으로 미룸). 지금 화단은 맵에 고정된 지형이라, 움직이게 하려면 별도 설계가 필요함 — 다음에 필요해지면 새로 브레인스토밍할 것.
