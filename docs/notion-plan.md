# 오늘 한걸음 개발 계획서

가천대 Tech for Impact 3팀 식물집사 · 작성 2026-10-29

개발자 3명이 4주 동안 1차 버전을 만들고, 그다음 4주 시범 운영을 함. 서비스 기획은 [오늘 한걸음 서비스 기획서](https://claude.ai/artifact/NzWckAZavug2FuwvZcMN9p)를 따르고, 이 문서는 누가 무엇을 언제 만드는지만 정함. 기능 상세와 완료 조건은 레포의 `docs/PRD.md`에 있음.

---

## 1. 역할 분담

화면 단위가 아니라 도메인 단위로 나눔. 한 사람이 한 흐름을 처음부터 끝까지 책임짐.

| 역할 | 담당자 | 맡는 범위 | 화면 |
|---|---|---|---|
| A 정원 | 미정 | 정원 화면, 꽃·새싹 애니메이션, 복귀 메시지 연출, 기록 보기 | 정원 홈, 완료 연출, 기록 |
| B 미션 흐름 | 미정 | 미션 제안·바꾸기·난이도 낮추기·완료·쉬기, 2·3단계 계획, 알림, 설정 | 오늘의 미션, 계획 정하기, 설정 |
| C 데이터·안전 | 미정 | 프로젝트 뼈대, Supabase 스키마·RLS·익명 로그인, 이벤트 로그, 지표 쿼리, 긴급 연결, 처음 시작 | 처음 시작, 긴급 연결 |
| D 콘텐츠·디자인 (개발 외) | 미정 | 픽셀 에셋, 새싹 캐릭터, 미션 문구 30~50개, 그린테라피 검수 | - |
| E 시범 운영 (개발 외) | 미정 | 참여자 모집, 동의서, 위기 대응 절차, 주간 설문 | - |

- C가 첫 주에 공통 기반(스키마, 타입, 이벤트 기록 함수)을 먼저 깔고, A와 B는 그 위에서 작업함.
- D와 E는 개발자가 겸하지 않는 것을 원칙으로 함. 겸하면 4주 개발 일정이 밀림.

## 2. 첫 주에 셋이 같이 확정할 것 (계약)

이 세 가지가 정해지면 각자 기다리지 않고 동시에 작업할 수 있음.

- [ ] 이벤트 사전: 이벤트 이름과 필드 (`docs/PRD.md` 4장 초안 리뷰)
- [ ] 테이블 구조와 TypeScript 타입 (C 초안, A·B 리뷰)

## 3. 일정과 작업 단위

작업 단위(슬라이스) 하나 = 브랜치 하나 = PR 하나. 슬라이스마다 실제 기기에서 확인한 뒤 머지함.

| 주차 | 슬라이스 | 담당 | 끝나면 되는 것 |
|---|---|---|---|
| 1주차 | S0 뼈대·스키마·이벤트 사전 | C (A·B 리뷰) | 앱이 켜지고, 익명 로그인 후 이벤트 1건이 DB에 쌓임 |
| 1주차 | S1 긴급 연결 | C | 모든 화면에서 두 번 안에 109 전화 화면이 뜸 |
| 1~2주차 | S2 미션 1단계 루프 | B | 미션 보기 → 바꾸기·줄이기 → 완료 또는 쉬기가 기록됨 |
| 1~2주차 | S3 정원과 꽃 | A | 완료 1건마다 정원에 꽃 1개가 보임 |
| 2주차 | S4 처음 시작 | C | 참여 코드 입력, 서비스 안내, 알림 시간 선택 후 정원 홈으로 감 |
| 2주차 | S5 복귀 메시지 | A + C | 2일 이상 공백 뒤 열면 "다시 왔네"가 뜨고 복귀 이벤트가 쌓임 |
| 3주차 | S6 2·3단계 계획 | B | 시간·장소, 활동·성공 기준을 직접 정하고 단계를 오갈 수 있음 |
| 3주차 | S7 알림과 설정 | B | 정한 시간에 하루 1회 알림, 끄기, 단계·시간 변경 |
| 3주차 | S8 기록과 한 줄 회고 | A | 꽃을 누르면 그날 활동과 메모가 보임 |
| 4주차 | S9 지표·배포·리허설 | C (전원) | 지표 4개 쿼리 결과 확인, TestFlight·안드로이드 내부 테스트 배포, 팀 내 1주 리허설 |

- 날짜는 기말 발표 일정이 나오면 주차 옆에 적음.
- 시범 운영은 동의서와 위기 대응 절차를 교수님·그린테라피에게 확인받은 뒤에만 시작함.

## 4. 작업 규칙

- `main`에 직접 푸시하지 않음. 브랜치 이름은 `s2-mission-loop`처럼 슬라이스 번호를 붙임.
- PR 리뷰어는 다른 역할의 개발자 1명. 긴급 연결·안내 문구·개인정보 관련 PR은 `needs-all-approvals` 라벨을 붙이고 3명 모두 확인 (작성자 확인 + 나머지 2명 Approve).
- 머지는 squash만 사용. 상세 규칙은 레포 `docs/CONVENTIONS.md`.
- 머지 전 체크: CI(`secrets`, `app`) 통과, 실제 기기에서 확인, PR에 스크린샷 첨부.
- 비밀 값(Supabase 키 등)은 커밋하지 않음. 레포가 공개라서 `.env`로만 관리함.
- 넣지 않기로 한 것(스트릭, 빨간 배지, 기분 점수, AI 상태 판단, 진단 문구, 개인정보 수집)이 PR에 들어오면 리뷰에서 반려함.
